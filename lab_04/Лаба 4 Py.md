**Тема:** Основы работы с системой контроля версий Git и веб-сервисом GitHub. 

**Цель работы:** Изучить основные принципы работы с системой контроля версий Git, научиться создавать локальные и удалённые репозитории, фиксировать изменения и размещать файлы проекта на GitHub. 

# **1. Теоретические сведения** 

**Git** - распределённая система контроля версий, предназначенная для отслеживания изменений в файлах и управления историей разработки проекта. 

**Локальный репозиторий** - хранилище проекта на компьютере, содержащее историю изменений. 

**Удалённый репозиторий** - хранилище проекта на сервере, в данном случае GitHub, которое позволяет сохранять и публиковать файлы проекта. 

**Коммит (commit)** - сохранённое состояние проекта с описанием внесённых изменений. 

**GitHub** - веб-сервис для хранения репозиториев, совместной разработки и публикации программного кода. 

# **2. Ход выполнения работы** 

# **2.1. Проверка установки Git** 

Для проверки корректности установки Git была использована команда: git --version 

В результате отображается установленная версия Git. 

# **2.2. Настройка Git** 

Для указания имени пользователя и электронной почты были использованы команды: 

git config --global user.name "Иван Доронин" 

git config --global user.email "ivandor95503@gmail.com" 

Эти данные используются для идентификации автора коммитов. 

# **2.3. Создание локального репозитория** 

Была создана рабочая папка для хранения лабораторных работ: 

mkdir programming-labs 

cd programming-labs 

Затем был инициализирован локальный репозиторий: 

git init 

В папке проекта появилась скрытая директория .git, в которой хранится история изменений. 

# **2.4. Создание структуры проекта** 

Для организации файлов лабораторных работ была создана папка: 

mkdir lab_01 

Внутри неё размещаются файлы с программным кодом и отчётами. Для просмотра текущего состояния репозитория используется команда: 

git status 

Она позволяет определить, какие файлы изменены, добавлены или ещё не отслеживаются Git. 

# **2.5. Фиксация изменений** 

Для добавления файлов в область подготовки коммита использовалась команда: 

git add . 

После этого изменения были зафиксированы командой: 

git commit -m "Initial commit: create structure and lab_01" 

Таким образом, создана первая запись в истории изменений проекта. 

# **2.6. Создание удалённого репозитория на GitHub** 

На сайте GitHub был создан новый репозиторий с названием programminglabs. 

# **2.7. Связывание локального и удалённого репозиториев** 

Для подключения локального проекта к GitHub используются команды: 

git remote add origin https://github.com/IvanDoronin7/programming-labs.git 

git branch -M main 

git push -u origin main 

Первая команда добавляет адрес удалённого репозитория, вторая задаёт название основной ветки main, а третья отправляет коммиты и файлы на GitHub. 

После успешной отправки содержимое локального репозитория становится доступным на странице созданного проекта. 

# **2.8. Использование Markdown** 

Для оформления отчётов используется формат Markdown. Он позволяет создавать заголовки, списки, таблицы, выделять текст и добавлять блоки программного кода. 

Файлы Markdown имеют расширение .md. Такой формат удобен для хранения отчётов непосредственно в репозитории GitHub.
